# Mission Summary Template

Use this structure after any substantial tutor mission.

## Mission Goal
- State the concrete problem solved by the mission.

## Business Meaning
- Explain why this matters for a real product, operator, or user.

## Architecture Meaning
- State the main system-design principle taught by this task.

## What Changed
- List the key files, modules, contracts, hooks, routes, or configs changed.
- State what each change was for.

## How It Works
- Explain the runtime flow step by step.
- Prefer data flow, signing flow, contract flow, or permission flow as appropriate.

## Security / Risk Notes
- List trust boundaries, attack surface, revert/failure scenarios, and operational constraints.

## What You Should Learn
- Extract 3 to 7 durable lessons.

## Frontend Analogy
- Map the concept to frontend/backend architecture the user already knows.

## Architect Lens
- Explain how to justify the design decision in a senior Web3/FinTech architect discussion.

## Open Questions
- State what remains weak, deferred, or product-dependent.

## Next Mission Context
- Explain how this mission sets up the next one.
